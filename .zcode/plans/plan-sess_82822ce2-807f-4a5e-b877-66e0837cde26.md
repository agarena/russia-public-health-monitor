# 「俄罗斯公共卫生事件公开信息观察站」完整实施计划

## 一、最终目标（完成的定义，全部满足即达标）

1. **上线的静态观察站**：GitHub Pages 上的 7 页静态网站（首页仪表盘、`/timeline`、`/sources`、`/evidence`、`/history`、`/methodology`、`/disclaimer`），忠实落实规格书的四维状态模型（观察阶段 O0–O8 / 关注等级 L0–L3 / 证据完整度 C0–C4 / 数据新鲜度，四者绝不合并）、六态信息状态机（CONFIRMED / REPORTED / UNCONFIRMED / CONTRADICTED / RETRACTED / UNKNOWN）、首页"10 秒理解"布局与信息密度上限。统一规格书中 `CONTRADICTED`/`CONFLICTING` 的命名不一致，全项目统一为 `CONTRADICTED`。
2. **可复现的开源项目**：MIT 协议 GitHub 仓库、双语 README、自搭建指南（fork → 配置 Secrets → 启用 Actions → 自动上线）、CI（持续集成）校验。README 以终态陈述产品定位，其中包含一条产品决策的终态表述：站点不做推广，依托 GitHub 的访问门槛自然筛选具备基本判断能力的受众（不写决策过程，符合文档终态纪律）。
3. **采集与更新 skill（AI 技能）**：仓库内 `skills/russia-monitor/`，供任何支持 skill 格式的 AI 代理调用；全部动作同时有等价的纯命令行入口（make 目标），无 AI 也能维护。六个动作：`collect` 采集、`review` 人工审核、`update` 再生成数据、`publish` 发布、`audit` 信息链路审计、`status` 健康检查。
4. **自动化数据流水线**：GitHub Actions 定时（默认每 2 小时，可调）执行 采集→归一化→去重→AI 结构化→评分→生成 JSON→构建→部署；单源失败不影响其他源；整体失败绝不破坏线上上一版数据（last-known-good 保护）。
5. **全链路可审计**：网站上任何结论可一键回溯——页面条目 → signal（信号记录）→ source（来源）→ 原始 URL 与原文；评级变化带理由与来源的变更记录；signals 以 append-only（只追加）JSONL 存储，git 历史即完整审计日志。
6. **合规护栏自动化**：禁词扫描（"爆发概率""预测准确率""席卷全球"等结论性/耸动表述）与首页条目上限校验作为部署门禁；AI 输出经 schema（数据结构）校验，且任何信息都不能被自动晋升为 CONFIRMED——CONFIRMED 只能由 S/A 级来源 + 维护者人工确认产生。
7. **事件生命周期闭环**：事件状态 active → stabilizing → closed 流转，及"What We Knew Then / What Was Later Confirmed"复盘页结构（先建好结构，事件结束时启用）。

## 二、技术选型

- **前端**：React 18 + TypeScript + Vite + Tailwind CSS；react-router 用 BrowserRouter + GitHub Pages 的 404.html 重定向方案；不引入重型图表库，趋势与来源关系图用轻量 SVG（可缩放矢量图形）实现；系统字体栈（不加载 webfont，兼顾性能与可达性）；数据在构建期内联进包，同时把 `public-data/*.json` 拷贝到站点根目录供外部直接消费。
- **数据处理**：Python 3.11+，httpx、feedparser（RSS 订阅格式解析）、pydantic（数据校验）、selectolax、dateparser、rapidfuzz；状态全部存 Git 内 JSON/JSONL，不引入数据库。
- **AI**：OpenAI 兼容接口，`AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` 三个环境变量可配（GLM/OpenAI 等均可）；仅做翻译、摘要、去重辅助、信息提取、状态分类建议；规格书 §72 的系统提示词原样固化为代码内常量；只对新增 signal 调用，控制成本。
- **测试**：pytest（流水线逻辑）、vitest + React Testing Library（前端组件）、ruff / eslint / tsc 静态检查。
- **部署**：GitHub Pages + GitHub Actions；密钥只放 GitHub Secrets，绝不进仓库与前端产物（CI 加扫描）。

## 三、仓库结构

```
russia-public-health-monitor/
├── frontend/            # React 站点（7 页）
├── collector/           # 采集：来源适配器、抓取调度
├── processor/           # 归一化 / 去重 / 事件关联 / AI 结构化 / 评分 / 生成公开 JSON
├── data/
│   ├── public-data/     # 生成的 7 个公开 JSON（event/signals/sources/timeline/cases/transmission/status），提交入库
│   ├── state/           # 内部状态：signals.jsonl（append-only）、rating_changes.json
│   └── history/         # 历史参照案例的结构化内容
├── config/
│   ├── sources.yaml     # 来源注册表（S/A/B/C/D 分级 + 采集方式 + 频率）
│   └── settings.yaml    # 评分权重、上限、禁词表等
├── skills/russia-monitor/   # 采集与更新 skill（SKILL.md + 脚本）
├── .github/workflows/   # collect.yml（定时采集部署）、ci.yml（校验）
├── docs/                # self-hosting.md 自搭建指南、data-schema.md
├── Makefile             # 统一命令入口（dev/collect/process/build/test/lint）
├── README.md / README.zh-CN.md / CHANGELOG.md / CONTRIBUTING.md / LICENSE(MIT)
```

## 四、里程碑（映射规格书五阶段）

### M0 项目骨架
git 初始化、上述目录、前后端脚手架、CI 骨架（lint + typecheck + build + test）、Makefile。验收：空白首页本地可跑，CI 绿。

### M1 前端全量 + 演示数据（规格书第一阶段）
- `types.ts` 定义规格书 §59–65 的七个数据模型；`data/mock/` 七个 JSON，`demo: true` 醒目标注，覆盖全部状态/等级/冲突/撤回形态。
- 七页全部实现：首页仪表盘（四维状态条、一句话摘要、关键变化≤6、已确认/未确认各≤5、未知≤5、下一观察点≤5、历史参照简版、数据源健康）；时间线页（垂直轴、纠错标注、状态配色+文字）；证据页（四栏+Unknown 独立栏）；来源页（表格+引用关系图）；历史页（2–3 个参照案例、相似/不同双栏、相似度只用低/中/较高）；方法论页（全部定义与局限）；免责声明页（含彩票概率比喻文案）。
- 全局：免责声明五处呈现（首页顶/详情/Footer/methodology/disclaimer）、响应式手机第一屏优先、克制视觉、SEO 基础（title/description/OpenGraph/sitemap/robots）。
- 验收：本地预览完整可看（按你的决策，不部署公网）；关键组件有渲染测试。

### M2 真实采集框架（第二阶段）
- `sources.yaml` 定稿：S 级（WHO 疫情暴发新闻 RSS、ECDC、俄联邦及涉事地方政府卫生部门公告页）；A 级（AP/BBC/TASS/Interfax 等 RSS，Reuters 经 Google News RSS 关键词中转并明确标注中转属性）；B 级（俄本地媒体）；C/D 级预留结构。实施时联网逐一核实可用性后定稿。
- 采集器框架：统一适配器接口、限速、合规 UA、尊重 robots、单源失败隔离；采集合规红线（不绕登录/验证码，只用官方 API、RSS 与合规网页采集）写进代码注释与文档。
- 初始真实数据种子：用联网检索核实事件当前公开信息，人工整理首批 signals；若公开信息不足，站点如实呈现低阶段与 UNKNOWN，不造数据。
- 生成原子性（temp→校验→替换）、last-known-good 保护、`status.json` 数据源健康。
- GitHub Actions 定时流水线上线；**创建公开仓库前与你确认**；AI key 配置进 Secrets。
- 验收：定时采集真实数据并自动部署上线。

### M3 多语言、去重与 AI 结构化（第三阶段）
三层去重（URL 规范化 / 标题相似 / AI 语义聚类）；来源独立性识别（origin/derived_from、引用链模式、独立来源计数）；AI 翻译与摘要（ru/en→zh）；signals 列表与详情（按时间/状态/等级/语言筛选）。验收：一条真实新闻从采集到上站的完整链路可演示。

### M4 状态判断与认知层（第四阶段）
内部 attention score（0–100，权重按 §32，前端不显示数字）；O/C/L 由规则计算**建议值**，维护者确认后生效（禁止舆情驱动自动升级）；Unknowns 与 Next Triggers 管理；评级变更记录（含理由与 source_ids）；趋势（↑→↓?）；历史对照内容完善；首页全部区块由真实数据驱动。验收：四维状态+未知+触发点全部由"流水线建议 + 人工确认"产出且可追溯。

### M5 自动化、质量与 skill 完整化（第五阶段）
skill 六动作完整；维护手册（编码 §99 维护者原则）；合规检查器上线为部署门禁；自动纠错（状态流转保留历史）；维护者提醒（Actions 失败/数据陈旧时开 issue 通知）；`docs/self-hosting.md` 自搭建指南；README 双语终态定稿；可选项：历史回测脚本（检验规则敏感度，不输出"准确率"）。验收：第三方按文档可独立搭建运行。

## 五、合规护栏（部署门禁，全部自动化）

1. 禁词/禁义扫描（命中即阻断部署；标记为来源引用的字段豁免）；2. 首页条目上限校验；3. 前后端数据 schema 一致性校验；4. CONFIRMED 晋升路径限制（S/A 级来源+人工确认，AI 最高只能建议 REPORTED）；5. 免责声明五处存在性检查；6. 前端产物密钥模式扫描；7. 采集失败只提示数据陈旧、不生成新风险信号。

## 六、需要你配合的事项

1. M2 时创建公开 GitHub 仓库（gh 已认证即可，创建前我会再确认）；2. 提供 OpenAI 兼容的 AI API key（如智谱 GLM），配到本地 `.env` 与 GitHub Secrets；3. 上线后的日常审核判断（skill 的 review 动作会引导你按规则决策）。

## 七、验收标准

规格书 §110 四类清单（视觉/内容/风险控制/技术）逐项全绿；§111 的 20 条铁律以"代码护栏 + 测试 + 文档"三重落实。开发纪律：本地预览服务器一律起在可管理的后台任务里、按 PID 清理，不触碰你的浏览器与长驻进程；git 提交随里程碑进行，公开推送前征得同意。
